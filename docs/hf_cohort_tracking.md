# Persistent Hugging Face cohort tracking

The feature follows a fixed discovered-population sample after repositories fall out of daily discovery. It is disabled by default. No enrollment, network calls, historical backfill, Silver/Gold rebuild, cloud provisioning or deployment happens automatically.

## Enrollment and reproducibility

The recommended fixed cohort is `hf_lifecycle_20261015_v2`, selection version 2. Its seed is `ai-model-lifecycle/hf-cohort/v2`; its cutoff remains `2026-10-13T23:59:59+00:00`. The original `hf_lifecycle_20261014_v1` registry remains unchanged for audit. Derive this correction offline from its embedded candidate population, rather than reading newer Raw snapshots:

```sh
python -m collector.cohort --root . --cohort-id hf_lifecycle_20261015_v2 \
  --from-cohort hf_lifecycle_20261014_v1 --cutoff 2026-10-13T23:59:59+00:00 \
  --selected-at 2026-10-15T08:40:08.947806+00:00 --size 1500 \
  --seed ai-model-lifecycle/hf-cohort/v2
```

Registries under `data/cohorts/` are written atomically. Reinitializing an existing ID returns its original registry without rewriting it, even with new archive data or parameters. Use a new cohort ID for another enrollment. IDs contain only letters, digits, underscores and hyphens (maximum 128 characters). Both timestamps must have timezones, with cutoff no later than selection. `--from-cohort` verifies the v1 candidate and discovery-input digests and requires its cutoff and size; it never opens Raw. Without that option, offline enrollment retains the existing completed-leg and cutoff reader.

Only completed `hf_models`, `hf_top_models`, and `hf_new_models` discovery legs contribute. Envelope timestamps must be at or before cutoff. The latest timestamp wins; equal timestamps prefer detail, top, then new. Creation after cutoff is excluded. All earlier observed days contribute, including IDs absent on the latest day. Private/disabled repositories and invalid identities or download/like counts are excluded. Boolean counts are invalid. Configured registries reject duplicate member IDs, nonboolean active flags, unsupported selection versions when supplied, and cohort IDs that differ from the requested registry. Minimal registries may omit optional selection metadata. IDs remain case sensitive; there is no rename or alias resolution.

Selection retains 500 popular IDs by downloads and 500 unselected recent IDs by creation time, with the existing lexical ID tie-breaks. For the remaining 500, group by author, falling back to namespace. Sort organizations by SHA-256 of UTF-8 compact JSON `[seed,"organization",organization]`; sort IDs inside each group by the same encoding of `[seed,"repository",repo_id]`. JSON uses `ensure_ascii=False`, separators `(',', ':')`, no Unicode or identity normalization. Hash ties use the original organization or repository string. Cycle through this fixed hash order, taking one repository from each nonempty organization per round. Thus neither input iteration order nor alphabetical organization order supplies the sample prefix. Quota shortfalls still fill from the remaining pool, and missing creation dates cannot enter recent. The registry records the seed, algorithm, encoding, immutable candidate population and input digests, cutoff and enrollment times. Explicit `select_members(..., selection_version=1)` retains the old algorithm solely for v1 replay; both registry versions remain readable for collection. See [the final architecture freeze](hf_cohort_architecture_freeze.md) for comparison and fresh-directory byte reproduction.

The supplied archive evidence is 47 observed days, 2026-08-28 through 2026-10-13, 32,986 unique discovered IDs, 7,054 observed on the latest day, and 9,711 with at least five observed days. These counts are supplied context, not a new live measurement. Default quotas are feasible for that population.

## Daily operation and provenance

Use `python -m collector --cohort hf_lifecycle_20261015_v2`, or set `HF_COHORT_ID=hf_lifecycle_20261015_v2` after deployment approval. The workflow passes the repository variable of that name; an unset/empty variable disables the feature. Existing four UTC schedule slots and concurrency guard remain in place. Enabling a live schedule or deploying cloud resources requires human approval; no live configuration is changed by this refinement.

The cohort leg runs after discovery. It reuses valid same-day stored measurements, preferring detail, then top, then new, and the first matching stored row within a leg. Reused envelopes retain actual discovery timestamps and all valid same-day discovery source names. Detail responses whose identity differs from their requested ID cannot be reused under the returned ID.

Missing active members are requested sequentially from the exact per-ID model endpoint. Polling requires today's UTC snapshot date and cannot precede selection or enrollment dates. HF `list_models` documents search/filter and pagination, not arbitrary exact-ID batch lookup: list discovery does not replace missing-member detail calls.

Successful cohort envelopes have `hf_id`, `cohort_id`, `fetched_at`, `http_status`, `body`, `source_leg`, `source_url` when available, and `discovery_sources`. Detail responses without CR or LF remain byte-verbatim inside the envelope. When the original HTTP body contains CR or LF (including a trailing newline), `body_raw_base64` preserves all original bytes as standard base64, and `body` contains the parsed object serialized as compact JSON. Each envelope remains one physical JSONL row; Silver and existing readers continue reading `body`. Recover exact response bytes with `base64.b64decode(envelope["body_raw_base64"], validate=True)` in Python. This additive encoding applies to newly collected responses; existing snapshots are not rewritten. Reused list items are serialized from stored parsed discovery JSON. Counts require nonnegative integers excluding bool; the response must be an object identifying the requested repository. Identity mismatches retain the returned ID in failure diagnostics without changing membership or mappings.

401/403/404/410/451 are terminal for that day. 429, connection failures, 5xx, other HTTP failures, invalid payloads and identity mismatches remain retryable. Failures live in manifest diagnostics, never synthetic zero measurements. Successful rows and terminal failures survive same-day partial reruns; retryable diagnostics are retained in attempt history. Unresolved IDs are eligible again on the next day. Failure never removes a member.

Each cohort run has a 1,800-second monotonic elapsed budget, starting at entry to the cohort leg and checked before each extra logical GET. An ongoing HttpClient call, including its bounded internal retries, may finish after the budget; a valid same-day success is saved. Remaining unrequested IDs go into a separate manifest `deferred` list with reason `budget_exhausted`. If UTC midnight arrives first, unrequested IDs are deferred with reason `snapshot_date_ended`; an actual response arriving after midnight remains an actual failed attempt. Deferred entries have no synthetic HTTP status or attempt timestamp and never become measurement rows or zero counts. Same-day resume loads persisted successes and terminal failures and polls only unresolved IDs. Retryable actual attempts continue into attempt history; deferrals are not attempts.

Coverage reports full cohort size, eligible requested count, represented attempts, successes, failures by reason, discovery reuse and observations obtained only through cohort requests. Coverage also reports `deferred` count and `deferred_by_reason`. Deferred IDs are excluded from `attempted` and `failed_by_reason`; attempted counts eligible IDs represented by a stored success or actual current failure, rather than individual HTTP retries or historical attempts. The ratio remains successful / all eligible members, including deferred and unavailable IDs in the denominator, or null when no members are eligible. The leg is partial whenever retryable failures or deferred IDs remain. An `ok` leg can include unavailable terminal members, so inspect coverage and failures rather than interpreting completion as healthy coverage. Old COMPLETE manifests receive no writes or calls. Existing manifests without the cohort leg mark it not applicable, including historical partial manifests.

Silver accepts successful rows from partial cohort legs. It keeps source observations and actual timestamps, adds `cohort_id` and `discovery_sources_json` to HF observation/repository tables, and preserves legacy discovery precedence for one canonical repository/day row. Cohort provenance is copied onto a discovery-winning canonical row. Cohort observations sort after existing discovery sources. Analysts can distinguish source file (`source_leg`) and originating discovery measurement through the cohort envelope.

## Runtime, deployment and cost

The cohort temporarily raises the existing HTTP client's request interval to at least 0.75 seconds and restores its prior setting afterward. This applies to internal bounded retries too. The documented anonymous HF API limit is currently 500 calls per five minutes and may change; the floor permits at most 400 cohort calls per five minutes. Discovery calls share the same client and API budget, so this is not a guarantee against rate limiting.

Per run, the theoretical maximum is 1,500 primary extra requests minus reused observations, or 4,500 total HTTP attempts with three attempts per logical GET (including retries). Across four daily retry slots this is up to 18,000 HTTP attempts per day before elapsed-budget limits; this is a theoretical ceiling, not an expected daily count. Persisted successes and terminal failures reduce subsequent runs, and typical completed-day reruns are no-ops. At the interval floor, 1,500 starts span about 18.75 minutes and 4,500 about 56.25 minutes before latency, backoff and 60-second request timeouts; the 30-minute budget prevents starting further logical GETs after its limit. Monitor coverage, deferrals and retry diagnostics before expanding the sample. Registry size includes the complete eligible population for reproducibility; JSONL growth is one successful member envelope per day.

The repository was independently verified public. Standard GitHub-hosted Actions minutes are free for public repositories. The general private paid Linux fallback rate is currently $0.006/minute ([official GitHub billing documentation](https://docs.github.com/en/billing/concepts/product-billing/github-actions), checked 2026-10-14). No AWS configuration is present; new AWS cost for this design is $0. Durable raw snapshots use existing Git commits and GitHub Actions; no artifacts service is introduced. Commit the offline registry before setting the repository variable. These are design and cost statements, not deployment or activation claims.

## Synthetic coverage example and research limits

For a synthetic cohort of 1,500 eligible members: 1,000 measurements reused through discovery, 400 detail successes, 70 terminal unavailable IDs and 30 retryable failures produce 1,500 represented attempts, 1,400 successes, coverage 93.33%, 1,000 discovery observations and 400 cohort-only observations. The cohort leg is partial. A rerun requests only the 30 retryable IDs; it does not refetch the 1,400 successes or 70 terminal failures. This example is illustrative, not archive evidence.

This is a fixed sample of repositories discovered by the existing interfaces, not an ecosystem-representative sample. Popularity and recency quotas, initial discovery filters, organization definitions and cutoff choice introduce selection bias. Organization spread limits concentration without making inclusion probabilities uniform. `downloads_30d` is a rolling 30-day download count, not a daily increment or lifetime total. Likes are engagement proxies, not unique users, deployment counts or causal adoption evidence. Availability failures are informative missingness, not zero adoption. Repository renames remain unresolved and may appear as identity failures. Membership is fixed even when a repository disappears or changes ownership. Actual timestamps matter for within-day comparisons; resumed collection can observe different times of day. Cohort observations do not reconstruct missed historical days.
