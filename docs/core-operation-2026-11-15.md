# Основной контур HF + OpenRouter + Vercel

Реализован регулярный сбор двух шлюзов в существующем collect workflow.
HF сохраняет ежедневную независимую выборку. OpenRouter и Vercel обновляются
за последние семь завершённых UTC-дней при каждом запуске. Старые ревизии
остаются в архиве. Cloudflare и Replicate этим workflow не вызываются.

Секрет OPENROUTER_API_KEY читается только шагом шлюзов. Публикующий шаг
сохраняет успешные исходные данные до проверки итогового статуса, поэтому
отказ одного API не уничтожает результат другого. Производные отчёты исключены
из Git; Markdown отчёт доступен в Actions summary и воспроизводится локально.

Точное соответствие OpenRouter строится по model_permaslug → canonical_slug
в каталоге того же дня → непустой HF ID. Хеши и указатели на строки сохранены;
будущие связи не переносятся назад. Источник/ledger с разными HF ID дают
ambiguous. Для Vercel действуют только явно проверенные интервальные связи.

## Реальная проверка

Живой запуск за 08–14.11 успешно запросил оба API. Все семь дней и все
метрики присутствуют. Доля токенов OpenRouter с точной HF-связью — **70,17%**,
Other — **4,79%**. Для Vercel доля атрибутированных текстовых токенов —
**25,67%** по текущему ledger. Это покрытие соответствий, не оценка открытости
весов или мирового рынка. Сформированы 60 кандидатов на проверку
(разные source/identifier/metric — не 60 уникальных моделей).

Полный набор: **248 тестов прошли**. После добавления последних сценариев
ошибок отдельно прошли **26 проверок gateway/pipeline**, Ruff чистый.
Независимое ревью проверило сохранность при отказах, статусы отчёта,
область доступа секрета и временную семантику соответствий.

## Запуск и публикация

```powershell
python -m gateway.pipeline --offline --end 2026-11-14
# Новый сбор требует ключа в окружении процесса:
python -m gateway.pipeline
```

Результат: data/analytics/core_report.md и core_report.json с очередью
проверки и ссылками на доказательства. Полная пересборка HF-витрин:
scripts/rebuild_analytics.ps1; флаг -FetchGateways дополнительно обновляет API.

Workflow подготовлен локально. Он начнёт работать после публикации изменений
пользователем. Удалённые workflow вручную не запускались, push не выполнялся.
