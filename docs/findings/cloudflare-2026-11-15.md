# Cloudflare Radar: проверка полезности 15 ноября 2026

Получены summary и дневные timeseries по моделям и задачам Workers AI.
Восемь запросов чтения, ни одного вызова inference. Исходные JSON, URL,
время получения и SHA-256 сохранены отдельно в
`data/external/cloudflare-radar/2026-10-16_2026-11-14/`.
Каждый запрос завершился HTTP 200 и success=true.

## Что удалось получить

| Срез | Результат |
|---|---|
| Дневные модели | 90 серий × 30 дней = 2 700 строк; top limit 100, Other не потребовался |
| Дневные задачи | 10 серий × 30 дней = 300 строк, в том числе Other |
| Полнота | Все запрошенные даты 16.10–14.11; сумма модельных долей по дням от 99,999992 до 100,000004% |
| Единица | Доля числа инференсов Workers AI; normalization=PERCENTAGE, units=inferences |
| Гранулярность | ONE_DAY; lastUpdated источника 15.11.2026 10:00 UTC |
| Идентичность | ID сервиса Cloudflare, не HF repository ID; соответствия автоматически не приняты |
| Цена данных | Зафиксированные исходные ответы суммарно небольшие; 4 запроса достаточно для следующего такого среза |

Метод [API](https://developers.cloudflare.com/api/resources/radar/subresources/ai/subresources/inference/methods/timeseries_groups_v2/)
использует `limitPerGroup`, а не `limit`: первые ответы с игнорируемым limit
вернули девять моделей и Other. Они сохранены, но в анализ взяты ответы
с документированным limitPerGroup=100. Источник принимает dateEnd включительно,
поэтому запрос до 15.11 00:00 вернул **31** метку времени. Последняя
метка исключается из дневной витрины явным фильтром дат; она не считается
31-м завершённым днём. Summary оставлен как ответ источника со своим
интервалом и не смешивается с дневным анализом.

## Полезность для проекта

Cloudflare полезен как независимое наблюдение спроса **внутри одного хоста**.
Состав нагрузки сильно отличается от LLM-шлюзов: summary источника сообщает
87,076989% Text Embeddings и 7,589551% Text Generation. Это показывает,
почему нельзя интерпретировать его общую модельную долю как долю на рынке
текстовой генерации. Средние из 30 дневных процентов составляют 86,0907%
и 8,1440% соответственно; это невзвешенные средние, а не pooled-показатели.
Дневная доля Text Generation варьируется с буднями и выходными.

В модельном срезе доминирует `@cf/baai/bge-m3`: средняя дневная доля
82,7221%. Для `@cf/openai/gpt-oss-120b` она равна 0,43036%, с 0,369108%
16 октября до 0,556879% 14 ноября. Увеличение доли не доказывает рост
абсолютного числа инференсов: абсолютный знаменатель не публикуется.
Это доли инференсов, не токенов, команд, людей или денег.

Общие названия модели недостаточны для объединения точных HF репозиториев.
Cloudflare явно [объявляет](https://developers.cloudflare.com/workers-ai/models/gpt-oss-120b/)
свой `@cf/openai/gpt-oss-120b` как Text Generation от OpenAI и
[bge-m3](https://developers.cloudflare.com/workers-ai/models/bge-m3/) как
Text Embeddings от BAAI. Для принятой связи нужны явная ссылка на веса
или отдельный проверенный ledger с вариантом и датой. В этом spike
такие связи не записывались; обрезание `@cf/` не является доказательством.

## Решение

**Сохранить как дополнительный источник, приоритет ниже OpenRouter.**
Для основной текстовой когорты сначала нужен подтверждённый список
Cloudflare Text Generation endpoints и точных HF-ссылок. До этого данные
лучше показывать отдельной панелью: профиль задач и наблюдаемый трафик
выбранных именованных моделей. Другие модальности могут стать отдельным
расширением проекта, но не должны менять нынешнюю когорту задним числом.

Данные [Radar](https://radar.cloudflare.com/about) опубликованы под
**CC BY-NC 4.0**, поэтому сохранены отдельно от CC BY 4.0 выгрузок шлюзов.
С 18 июня методика [изменилась](https://developers.cloudflare.com/changelog/post/2026-06-18-radar-workers-ai-inference-metric/)
с уникальных аккаунтов на число инференсов, с пересчётом истории. Необходимо
хранить ревизии; повторная выгрузка не гарантирует прежние значения.

## Воспроизведение

```powershell
# Ключ только в process environment, не в файле:
python -m scripts.cloudflare_spike --start 2026-10-16 --end 2026-11-14
# Только анализ сохранённых байтов, без ключа и HTTP:
python -m scripts.cloudflare_spike --analyze-only
python -m pytest -q tests/test_cloudflare_spike.py
```

Выходы: `data/analytics/cloudflare_radar_usage.parquet` и
`data/analytics/cloudflare_radar_quality.json`. Три теста проверяют исключение
пограничного дня, полноту дат и знаменателей, документированное имя лимита.
Тесты прошли, Ruff без замечаний. Общий importer шлюзов их не подхватывает:
Cloudflare использует отдельный `_manifest.json` и отдельную схему.
